# 两地光（Two-Place Light）

一台只关心光的小设备：把**威海**（老家）与**天津**（学校）此刻的太阳高度、日出日落，以及
今天还剩多少光，放在同一块 240×320 的屏上。

全部在 MCU 上算出来。不联网，没有图片素材，没有音频，除了基线已经启用的两个 Montserrat
字号之外没有额外字体。

## 操作

| 操作 | 作用 |
| --- | --- |
| `上` / `下` | 上一页 / 下一页 |
| `确定` 短按 | 背光 100% → 60% → 30% 循环 |
| `确定` 长按 | 息屏；任意键唤醒 |
| 对时页 `上` / `下` | 调整高亮字段 |
| 对时页 `确定` 短按 | 下一字段；在最后一个字段上即提交 |
| 对时页 `确定` 长按 | 取消 |

## 三个页面

1. **ARC** —— 全天太阳高度曲线 + 地平线，以及当前时刻的两个标记：实心是威海，空心是天津。
2. **PAIR** —— 两边数字并排：此刻高度、日出、日落，以及哪边更亮。
3. **LEFT** —— 距离下一次日落/日出还有多久、民用晨昏时刻、明天比今天多或少多少光。

## 时间从哪来

板子没有独立 RTC 芯片。时间走 ESP32-C3 的 RTC（`CONFIG_NEWLIB_TIME_SYSCALL_USE_RTC`），深睡眠
期间可以继续走——但那要等自动休眠做出来才有意义，而**目前还没做**。在休眠之前，设备醒着时
每秒刷新一次，真正断电后时间会丢。

本仓库从未验证过按键以外的输入通道（串口 stdin），所以对时只能用三个按键完成：RTC 里没有
可信时间时开机直接进对时页，并用 NVS 里上次对时的时间戳做预填起点。时间不可信时，界面不会
装作知道。

## 还没做

- 空闲自动深睡眠（`bsp_display_prepare_deep_sleep` + `bsp_button_prepare_deep_sleep`，以及
  `main/key_guard.h` 里的唤醒键屏蔽）。没有它，设备会一直按整机运行电流放电，500 mAh 电芯
  撑不了多久。
- 背光档位跨重启保存。
- 中文标签；加之前先过一遍字体检查清单。


## 文件

| 路径 | 职责 |
| --- | --- |
| `main/solar.c` | 太阳几何：赤纬、时差、日出日落、高度角、方位角 |
| `main/civil_time.c` | epoch ↔ 日历换算、本地日边界 |
| `main/places.c` | 两个坐标与显示名 |
| `main/app_clock.c` | RTC 读写与最近一次对时记录（NVS） |
| `main/app_state.c` | 页面与背光状态机 |
| `main/app_setup.c` | 三键对时状态机 |
| `main/ui.c` | 四个页面 |

`main/demo_*.c` 与基线的像素菜单仍留在树里作参考，但已不参与构建：派生应用必须有自己的界面。

## 换成你关心的两个地方

改 `main/places.c`。坐标是市中心附近的近似值（±0.05°），远小于一分钟的日出误差量级。
