# 两地光（Two-Place Light）

一台只关心光的小设备：把**威海**（老家）与**天津**（学校）此刻的太阳高度、日出日落，以及
今天还剩多少光，放在同一块 240×320 的屏上。

天文计算全部在 MCU 上完成。没有图片素材，没有音频，除了基线已启用的两个 Montserrat 字号之外
没有额外字体。网络只用来做一件事：对时。

## 操作

| 操作 | 作用 |
| --- | --- |
| `上` / `下` | 上一页 / 下一页 |
| `确定` 短按 | 背光 100% → 60% → 30% 循环 |
| `确定` 长按 | 息屏；任意键唤醒 |
| 抢时间阶段 `确定` 长按 | 放弃联网，改用手动对时 |
| 对时页 `上` / `下` | 调整高亮字段 |
| 对时页 `确定` 短按 | 下一字段；在最后一个字段上即提交 |
| 对时页 `确定` 长按 | 取消 |

## 三个页面

1. **ARC** —— 全天太阳高度曲线 + 地平线，以及当前时刻的两个标记：`*` 实心是威海，`o` 空心是天津。
2. **PAIR** —— 两边数字并排：此刻高度、日出、日落，以及哪边更亮。
3. **LEFT** —— 距离下一次日落/日出还有多久、民用晨昏时刻、明天比今天多或少多少光。

## 时间从哪来

RTC 里没有可信时间时，按下面顺序抢时间：

1. **Wi-Fi + SNTP**。有凭证就连路由器，问 `ntp.aliyun.com` 要时间，同步成功就写进 RTC。
   两个城市都在 UTC+8，因此不需要时区表。
2. **配网热点**。没凭证或连不上时开一个 SoftAP `TwoPlaceLight`（WPA2，密码 `lingan-is-so-cute`）。
   手机连上它，打开 `http://192.168.4.1`，填 Wi-Fi 名和密码；设备存进 NVS 后重启。
   热点开着的时候，射频范围内谁都能访问这个配置页，所以它是一扇临时窗口，不是常驻服务。
3. **三键手动对时**。在第 1–2 步里长按 `确定` 直接跳过联网：`上/下` 调字段，`确定` 跳下一个，
   在分钟字段上再按一次提交，长按 `确定` 取消。

板子没有独立 RTC 芯片。时间由 ESP32-C3 的 RTC 经 newlib 维持
（`CONFIG_NEWLIB_TIME_SYSCALL_USE_RTC`），深睡眠期间不丢，但真正断电会丢——所以开机要走上面
这套流程。时间不可信时界面显示 `--:--`，不猜。

## 文件

| 路径 | 职责 |
| --- | --- |
| `main/solar.c` | 太阳几何：赤纬、时差、日出日落、高度角、方位角 |
| `main/civil_time.c` | epoch ↔ 日历换算、本地日边界 |
| `main/places.c` | 两个坐标与显示名 |
| `main/app_clock.c` | RTC 读写与最近一次对时记录（NVS） |
| `main/app_state.c` | 页面与背光状态机 |
| `main/app_setup.c` | 三键对时状态机 |
| `main/net_wifi.c` | STA 连接、配网 SoftAP + HTTP 表单、凭证存取 |
| `main/net_time.c` | SNTP 对时 |
| `main/prov_parse.c` | 配网表单解析（URL 解码与长度规则） |
| `main/ui.c` | 五个页面 |

`main/demo_*.c` 与基线的像素菜单仍留在树里作参考，但已不参与构建：派生应用必须有自己的界面。

## 还没做

- 后台定期重新对时：目前只在开机、且时间不可信时才同步。
- 空闲自动深睡眠（`bsp_display_prepare_deep_sleep` + `bsp_button_prepare_deep_sleep`，以及
  `main/key_guard.h` 里的唤醒键屏蔽）。没有它，设备会一直按整机运行电流放电。
- 背光档位跨重启保存。
- 中文标签；加之前先过一遍字体检查清单。

## 换成你关心的两个地方

改 `main/places.c`。坐标是市中心附近的近似值（±0.05°），远小于一分钟的日出误差量级。
